## Known limits

v1.0 is frozen: these are documented, not tuned further (one tuning round only, to avoid
overfitting the prompt to 11 scenarios).

| Limit | Numbers | Why | Kind |
|---|---|---|---|
| Overconfidence | every run at confidence ≥ 0.8; avg 0.96 vs. accuracy 0.88 (dev 0.78); the 4 wrong dev runs (s06 ×3, s08) at 0.9–1.0 | the small model does not judge its own certainty; a written confidence scale (v3) barely moved it (1.00 → 0.96) | model limit |
| s06 label | cause found 0/3, category 0/3 (`infra_crash` instead of `dependency_failure`) | the snapshot never shows that `payments` is an external provider: it is a container in the same compose file | scenario ambiguity |
| s08 anchoring | cause 2/3, category 1/3 | the agent quotes the lowered `statement_timeout` (30s → 250ms) but keeps the earlier slow-query commit as the main cause | agent limit (anchoring) |
| Holdout no longer blind | v3 holdout 15/15 category | holdout runs were read before tuning; two lines of the category rule come from s04 and s10 | evaluation limit |
| No baseline | — | dropped 2026-10-22; the cost of the loop vs. a single prompt is not measured | scope choice |
| Small set | 11 scenarios × 3 runs | each scenario is a recorded live incident (~50 min each); small differences are trends, not significant results | scope choice |
| Token cost of rules | 38.5K → 45.4K tokens per dev run (+18 %) from v2 to v3 | every added rule is sent on every call | trade-off |

## Cost

$0: all runs on the Gemini free tier (15 RPM, 500 requests/day). About 1.45M tokens for
the 33 runs (43.9K per run). One run takes ~4 min with the client-side throttle
(`LLM_RPM=14`), so the full 11 × 3 eval takes about 2 hours and fits in one day's quota.

## Reproduce

Same model and prompt: `LLM_MODEL=gemini-3.5-flash-lite` in `.env`, code at tag `v1.0`.

```
git checkout v1.0
.venv/Scripts/python -m eval.run_all --runs 3 --out runs/<date>/agent_v3   # all 11 scenarios x 3
.venv/Scripts/python -m eval.report runs/2026-10-22/agent_v3              # re-score saved runs, no LLM call
.venv/Scripts/python scripts/export_ui_data.py runs/2026-10-22/agent_v3 runs/2026-10-22/agent_v3_holdout   # viewer data
```

Re-scoring the saved runs gives the same tables (checked 2026-10-23). A new live run gives
close but not identical numbers: the model's output varies between runs, which is why each
scenario runs 3 times (check on 2026-10-23: s01 × 1, cause found, evidence 3/3).

## Future work

  alternative), instead of asking the model. Would be a separate v1.1 experiment.
- A scenario signal that tells an external dependency from the app's own containers.
- A one-shot baseline to measure what the loop adds per token spent.
- A fresh, never-read holdout set for a new blind measure.
